# Threshold ECDSA (real MPC)

This package implements **threshold ECDSA (secp256k1)** key generation and
signing with [bnb-chain/tss-lib](https://github.com/bnb-chain/tss-lib) — the
production cryptographic core that replaces the Phase 0/1 single shared key.

A `k`-of-`n` key is generated by `n` parties; any `k+1` (= threshold+1) can
co-sign. **The private key is never reconstructed** at any point. The output is a
standard 65-byte `[R || S || V]` Ethereum signature that recovers the shared
address and verifies like any other.

## Why it's behind a build tag

The package is gated by `//go:build tss` for two reasons:
1. tss-lib's generated protobuf type carries a `DoNotCopy` marker that makes
   `go vet`'s copylocks analyzer fail on the (unavoidable, correct) channel
   receive — so it's excluded from the default `go vet ./...`.
2. Key generation does safe-prime work (~tens of seconds) that shouldn't run on
   every default `go test`.

## Run the proof

```bash
cd services/mpc-signer
go test -tags tss -vet=off ./tss/ -run TestThresholdKeygenAndSign -v
```

This performs a real 2-of-3 distributed keygen, signs a hash with two parties,
and asserts the signature recovers the threshold address.

## In-process vs. production

For testability the parties run as goroutines with in-memory message routing.
The protocol, message handling and save data are identical to a real deployment;
only the transport differs. Production runs **each party in its own isolated
process/host** with authenticated transport, and seals each key share in a
separate Vault path so no single host can reconstruct the key. Wiring the live
multi-party transport and per-customer DKG ceremony is the Phase 2 task; this
package proves the cryptography is correct and Ethereum-compatible today.
