# Sepolia accepted a threshold-signed transfer (2026-10-11)

Before this, the EVM path had only been driven against a private multi-node test network. This is the
first transaction a public EVM network has mined that was signed by the platform's threshold key.

| | |
|---|---|
| Network | Ethereum Sepolia (chain id 11155111), reached through a public RPC |
| Key | `0xc378bf1A3085000AeD970aFc3fBBc6F0240fd129` (2-of-3 threshold ECDSA, created by DKG across three pods) |
| Recipient | `0x000000000000000000000000000000000000dEaD` |
| Amount | 100,000,000,000,000 wei (0.0001 ETH), EIP-1559 transaction |
| Signed by | parties 1 and 2 of 3 |
| Transaction | `0xb9f5004d1f22660d116f68e866144ffbf030abdb82b3370df99898e08d035a9c` |
| Block | 11890164, receipt status success |
| Explorer | https://sepolia.etherscan.io/tx/0xb9f5004d1f22660d116f68e866144ffbf030abdb82b3370df99898e08d035a9c |

Run with `infrastructure/kind/sepolia-test.sh` on the staging deployment (commit `fe0ebe9`). The network
reported the same transaction hash the platform computed locally, so the signature recovered to the
key's address.

The platform refused the first attempt for missing Travel Rule details (it has no price source for ETH, so
treats any native transfer as over the R5000 threshold). The script now supplies clearly-labelled testnet
details. A pilot customer will need to supply Travel Rule details on native transfers until a price source
is configured.

Shows: the EIP-1559 transaction format and the threshold ECDSA signature are accepted by a real public
EVM network. Does not show: mainnet behaviour, ERC-20 transfers on a public chain, or behaviour under load.
